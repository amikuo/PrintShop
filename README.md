# PrintShop V2.3 規格管理重做版

依 Business_Rules_Final_v4.md 重做：
- 規格／常用規格兩個可收合模組
- 品項為根節點
- 材質、尺寸、常用數量、單位隸屬品項
- 後加工獨立
- `⋯` 安全管理：編輯／停用／刪除
- 已有歷史使用的規格禁止直接刪除
- 常用規格整組保存，帶入後可修改
- 交易修改不反向污染規格資料庫

## V3.0
- 新增「資料管理」頁：一致性立即備份、備份清單與下載。
- 完整還原前自動建立保命備份，且需輸入「完整還原」二次確認；不合併資料。
- 新增 schema version / migration 基礎，V2.9.3 資料庫會原地升級至 schema 1。
- 程式 ZIP 不包含 `database/printshop.db` 與任何備份，因此更新程式不會覆蓋正式資料。
- Windows 安裝需求加入 `tzdata`。

### V2.9.3 → V3.0 更新原則
1. 關閉正在執行的 PrintShop。
2. 先自行複製一份 `database/printshop.db` 到安全位置。
3. 將 V3.0 ZIP 直接解壓到原 PrintShop 目錄並允許更新程式檔；ZIP 本身不含正式資料庫。
4. 執行 `pip install -r requirements.txt`，再以原方式啟動程式。
5. 開啟首頁確認既有客戶、報價、訂單、專案與規格；再到「資料管理」執行一次立即備份並測試下載。

若要把營業資料永久放在程式目錄之外，可在啟動前設定 `PRINTSHOP_DATA_DIR`；該目錄下需包含 `database/printshop.db`，備份會寫入同一資料根目錄的 `backups/`。


## V3.1
- 每天首次使用時自動建立每日備份，保留最近 30 份。
- 每月另建封存備份，保留最近 12 份。
- 手動備份與還原前保命備份不會被自動刪除。
- 新增 `Start_PrintShop.bat` 一鍵啟動並避免重複開啟伺服器。
- 新增登入 Windows 後自動啟動的設定與取消工具。
- 新增只對私人網路開放 TCP 5000 的防火牆工具。
- 新增區網 IP／MAC 查詢工具與路由器 DHCP 保留位址說明。

店內 Windows 的操作順序請閱讀 `店內主機設定說明.md`。


## V3.2
- 新增訂單時可指定「建立日期」，預設為台灣今天，並可補登過往訂單。
- 歷史訂單編號使用所選日期的 `YYMMDD`，流水號會避開當日既有報價與訂單。
- 智慧搜尋、首頁訂單搜尋與訂單列表改依實際建立時間判斷新舊。
- 既有訂單修改、報價轉訂單及其他 V3.1 功能維持不變。


## V3.2.1
- 「建立時間」簡化為「建立日期」，只需選擇年月日。
- 預設今天；補登過往訂單時不必輸入時與分。
- 系統自動處理內部時間、歷史訂單編號與智慧搜尋排序。


## V3.3
- 首頁搜尋支援空白、半形 `+` 與全形 `＋` 分隔多個條件。
- 任一條件符合即可出現，依符合條件數量由多至少排序，再比較欄位相關性與建立日期。
- 搜尋結果卡直接顯示相關品項、完整規格、數量、單價、小計與備註。
- 完整訂單在首頁唯讀 Modal 顯示，支援上一筆／下一筆，關閉後不會清除搜尋結果。


## V3.3.1
- 修正測試伺服器可能占用正式 TCP 5000，導致瀏覽器看到測試資料的風險。
- 一鍵啟動會核對 5000 上的 PrintShop 是否使用目前程式目錄的正式資料；不同資料實例會顯示警告且不開啟。
- 正式啟動明確指定資料目錄、5000 連接埠並關閉 debug／reloader。
- 可用 `PRINTSHOP_PORT` 指定開發測試連接埠，未來測試不得再使用正式 5000。


## V3.4
- 報價與訂單內容頁新增「匯出 PDF」，直接下載 A4 客戶文件。
- 採用深灰色廣達數位印刷 Logo；每一頁固定重繪頁首、左側品牌區、客戶資料與表格欄名。
- 品項過多時自動分頁，最後一頁才顯示金額摘要與三條固定印刷備註。
- 訂單 PDF 頁首顯示應付，已有收款時才顯示已收款；報價 PDF 顯示小計、稅額與總計。
- PDF 匯出只讀取資料，不會修改報價、訂單、收款或正式 SQLite 資料庫。
- 本版新增 `reportlab`；覆蓋程式後須重新執行 `pip install -r requirements.txt`。


## V3.4.1
- 訂單 PDF 頁首改為一律顯示「應付」與訂單總額，不再使用「未收」作為主要金額。
- 有收款時才在應付金額旁以小字顯示「已收款」及金額；尚未收款時該位置留白。
- 訂單右下金額區只保留小計、外加稅與總計，不再重複顯示已收及未收。


## V3.4.2
- PDF 品項表頭由固定的「規格(mm)」改為「規格」。
- 規格內容仍依使用者輸入原樣呈現，可自行包含 mm、cm、英吋或其他單位。


## V3.4.3
- PDF 品項表頭與內容套用一致對齊：商品敘述靠左、規格置中、單價靠右、數量置中、金額靠右。
- 序號維持置中。


## V3.5
- 客戶主檔新增「個人／公司或單位」類型；個人只需填姓名，不再重複顯示聯絡人。
- 客戶列表新增清楚的「編輯」按鈕，可直接修改公司／單位名稱或個人姓名。
- 客戶改名會保留舊名稱，仍可從客戶搜尋、首頁智慧搜尋及交易歷史搜尋找到既有資料。
- 報價與訂單只連結既有客戶，不再於編輯交易時暗中修改客戶主檔。
- 資料庫升級至 Schema 2；既有名稱與聯絡人相同的資料會原地轉為個人並清除重複欄位，不會重建或刪除營業資料。
- PDF、客戶列表與搜尋結果會自動避免重複顯示相同的客戶姓名與聯絡人。

### V3.4.3 → V3.5 更新步驟
1. 關閉 PrintShop，並先從「資料管理」建立一份立即備份。
2. 將 V3.5 ZIP 直接解壓到原 PrintShop 目錄並允許覆蓋程式檔；ZIP 不包含正式資料庫。
3. 執行 `pip install -r requirements.txt`，再以 `Start_PrintShop.bat` 啟動。
4. 到「客戶」確認個人／公司或單位類型，並測試修改一筆客戶名稱。
5. 以修改前的舊名稱進行首頁智慧搜尋，確認仍可找到原有訂單。


## V3.6
- 將原本分開的「客戶類型」與「分類」整合成單一欄位：個人、學校、政府、公司、宗親會／協會。
- 個人只顯示一個姓名；其他類型先顯示所屬單位，有填聯絡人時才接著顯示聯絡人。
- 所有類型的聯絡人均為選填，沒有固定聯絡人時可直接留白。
- 客戶表單會依類型切換名稱欄標題，客戶列表不再顯示重複的分類欄。
- 資料庫升級至 Schema 3；依目前測試階段的決定，既有客戶一律先轉為個人，客戶 ID 與所有歷史報價、訂單及專案連結維持不變。

### V3.5 → V3.6 更新步驟

## V3.7
- 專案內容頁新增「匯出專案 PDF」。
- PDF 左側固定顯示專案請款單位，內容依每張有效訂單的工作單位分組。
- 每個工作單位列出品項後顯示單位小計；一般模式訂單歸入「未分工作單位」。

- 本版沿用 Schema 3，不變更正式資料庫結構。
